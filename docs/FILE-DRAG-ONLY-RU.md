# Меню только при перетаскивании файлов (Windows)

## Что было не так

DragShift считал «жестом» всё, где зажата левая кнопка мыши, нажат Shift и мышь сдвинулась. То же самое происходит при выделении текста с Shift, перемещении окон, выделении рамкой, поэтому меню появлялось в любых программах и через долю секунды пряталось.

## Что стало

Теперь на этот жест меню сразу не показывается. Программа ждёт **доказательства, что тащат именно файл**:

1. **Невидимое окно-щуп** (160×160 px, прозрачность 1/255) едет за курсором. Когда Windows начинает настоящее перетаскивание файла, она передаёт данные окну под курсором. Если это локальные файлы, щуп сообщает об этом, и тут же появляется меню. Выделение текста и перемещение окон никаких данных не передают, поэтому щуп молчит и ничего не появляется.
2. **Запасной признак:** если щуп не услышал файлов, но рядом с курсором дольше четверти секунды висит «картинка перетаскивания» Windows (окно `SysDragImage`), это тоже считается перетаскиванием.

Видео, фото, PDF и любые другие файлы работают одинаково: для проверки важно только, что тащат файл с диска.

Если отпустить кнопку мыши или Shift до подтверждения, программа перестаёт ждать. Если Shift нажать снова, ожидание начнётся заново.

## Как поставить

Ничего отдельно ставить не нужно: файлы `dragshift\trigger.py` (из оригинала убраны 2 строки, добавлено около 60), `dragshift\dragprobe.py` и `tests\test_dragprobe.py` уже внутри `DragShift-video-upscale.zip`. Достаточно распаковать архив в папку проекта и запустить `run.bat`. Для готовой программы: `build_exe.bat`.

Проверить новые тесты (из папки проекта, с включённым `(.venv)`):

```powershell
python -m pytest -q tests\test_dragprobe.py
```
В конце `13 passed`.

## Как проверить руками (чек-лист)

| Что делаете | Что должно быть |
|---|---|
| Тащите фото из проводника, зажимаете Shift | Меню появляется (после небольшого движения мыши) |
| То же с видео `.mp4` | Меню с кольцами Convert и Tools для видео |
| Файл с рабочего стола | Меню появляется |
| Выделяете текст мышью (Блокнот, браузер) и зажимаете Shift | Ничего не появляется |
| Двигаете окно за заголовок с зажатым Shift | Ничего не появляется |
| Выделяете файлы рамкой в проводнике с Shift | Ничего не появляется |

Что решила программа, записывается в `%LOCALAPPDATA%\DragShift\log.txt`:

- `gate: file drag confirmed (probe)` — файл распознан щупом;
- `gate: file drag confirmed (drag picture)` — распознан по запасному признаку;
- `gate: Shift+drag ignored, no file drag detected` — это был не файл (выделение, окно и т. д.).

## Если меню перестало появляться при перетаскивании файла

Верните прежнее поведение, пока разбираемся. Для запуска из исходников:

```powershell
$env:DRAGSHIFT_ANY_DRAG = "1"
```
```powershell
python run.py
```

Для готовой программы (постоянно, после этого перезапустите DragShift):

```powershell
setx DRAGSHIFT_ANY_DRAG 1
```

Чтобы снова включить фильтр: `setx DRAGSHIFT_ANY_DRAG ""` (и перезапуск программы).

Пришлите последние строки `log.txt` с `gate:`, и я пойму, на каком шаге остановилось.

## Ограничения

- Работает только на Windows. На macOS и Linux поведение прежнее.
- Перетаскивание из программы, запущенной от имени администратора, в обычный DragShift Windows не пропускает вообще. Так было и раньше.
- Если приложение отдаёт не файлы, а «виртуальные файлы» (например, вложения из Outlook), щуп их не увидит. Такие перетаскивания распознаются только по запасному признаку.
- Сценарии `demo\e2e_windows.py` рассчитаны на мгновенное появление меню. С фильтром меню появляется после первого движения мыши, и в них могут понадобиться паузы. Я эти сценарии не запускал.
